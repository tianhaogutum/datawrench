# Fixture provenance

`orders.csv` and `orders.yaml` are generated locally by `make_fixtures.py`, using
the real pandas `DataFrame.to_csv` and Pandera `DataFrameSchema.to_yaml` APIs.
They model an order extract with independent numeric and cross-row uniqueness
failures. They are synthetic, contain no personal data, and are not claimed to
be a production incident. The quoted multiline UTF-8 record is deliberately
part of the retained duplicate pair.

Tests generate further files through real upstream writers, or explicitly use
handwritten byte fixtures for invalid syntax and newline edge cases. No test
downloads data or sends data to a service.

`orders-pandera-0.26.1.yaml` was generated by the actual PyPI Pandera 0.26.1
`DataFrameSchema.to_yaml` writer, installed temporarily under `vendor-tmp/`
with its `io` extra. It represents the same rules as `orders.yaml` and retains
the legacy serialization's version, check-options, and null/default fields.
The temporary upstream package directory was deleted afterward. The initial
generation attempt without the old IO extras failed as expected; installing
those extras allowed generation. The current Pandera 0.36.0 reader consumes
the legacy fixture unchanged; the regression test compares actual failures
and reduces the selected uniqueness failure with both versions' YAML shapes.
