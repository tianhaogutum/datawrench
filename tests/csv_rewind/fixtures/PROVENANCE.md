# Fixture provenance (`datawrench csv-rewind`)

* `csvkit-FY09_EDU_Recipients_by_State.csv` is an unmodified upstream real-data
  example from csvkit tag **2.2.0**: [raw source](https://raw.githubusercontent.com/wireservice/csvkit/2.2.0/examples/realdata/FY09_EDU_Recipients_by_State.csv).
  Downloaded 2026-11-11, 3001 bytes, SHA-256
  `809b938a927e1a216e9a12bf6d3c58157cd6423cac0309836e9bb5db65783746`.
  It contains state codes, quoted comma-separated amounts, and empty final cells.
  The csvkit repository is MIT-licensed; its notice is kept in
  `licenses/csv-rewind/csvkit-COPYING` and `THIRD_PARTY.md`.
* `csvkit-bom-semicolon.csv` is real csvkit 2.2.0 `csvformat` output from
  `csvformat --add-bom -D ';' survey.csv` (2026-11-11).
  It is 117 bytes, SHA-256
  `45c61dd908aa08c84438e1935ffa4efc5148f0b2471d8eadfb256b2b03d0b99c`.
  The test independently compares decoded fields with the original survey input.
* `duckdb-*.csv`, `duckdb-no-header.tsv`, and `duckdb-compressed.csv.gz` are real
  **DuckDB 2.0.0 `COPY` output**, generated by
  `examples/csv_rewind/make_fixtures.py` from the supplier-style text rows
  in that script. This uses an actual producer, not handcrafted CSV formatting.
  It covers comma/semicolon/pipe/tab delimiters, doubled/backslash quotes,
  CRLF, multiline/non-ASCII fields, an empty field, absent headers and gzip.
  `duckdb-manifest.json` records the original rows, options and file hashes.
  `duckdb-canonical.csv` is produced from genuinely typed engine values.
* `duckdb-multi-{pipe,colon,arrow}.csv[.zst]` are pinned DuckDB 2.0.0 COPY
  outputs, generated by `examples/csv_rewind/make_advanced_fixtures.py`.
  `advanced-manifest.json` records delimiters, values and hashes. Use 2.0+
  to regenerate: 1.4.3 and 1.5.6 COPY silently emitted only the first delimiter
  character, so their output cannot test a multi-character reader configuration.
  The older readers are tested against the pinned 2.0 producer files.
* `python-csv-utf16-cr-176.csv` and `python-csv-utf16-cr-207.csv` are unmodified
  Python 3.12.14 `csv.writer` output from a seeded independent-producer sweep
  (seed 30202, cases 176 and 207).
  Their adjacent JSON files retain exact original rows, dialect and SHA-256.
  They reproduce headerless UTF-16/CR sniffer failures with multiline values.
* `survey.csv` (also `examples/csv_rewind/survey.csv`) is a synthetic,
  handwritten sample with leading-zero codes, integers above 2^53, day-first
  dates, decimal trailing zeros and uppercase booleans. It is not represented
  as a public supplier dataset. Tests also create deliberately invalid inputs
  locally.

Tests make no network requests and use committed fixtures. Generation is an
explicit command; upgrading DuckDB does not silently replace fixture bytes.
