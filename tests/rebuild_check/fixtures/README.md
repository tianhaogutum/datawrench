# Fixture provenance

- `chinook.sql` is the unmodified SQLite SQL dump from the Chinook sample database, commit `7f67772503d71ba90f19283c38e93923addb43fa`. Downloaded 2026-11-11 from https://raw.githubusercontent.com/lerocha/chinook-database/7f67772503d71ba90f19283c38e93923addb43fa/ChinookDatabase/DataSources/Chinook_Sqlite.sql . Size 595545 bytes; SHA-256 `caf31d698a4a79c628215b552dfe6575e71be052ae02b8f18e763498f55f5d44`. Its original license is `chinook.LICENSE.md` (MIT, Copyright (c) 2008-2024 Luis Rocha). Real disk SQLite files are generated from it during tests, not mocked.
- `django-5.2-rebuild.sql` was emitted by Django **5.2.19**'s actual SQLite `connection.schema_editor(collect_sql=True, atomic=False).alter_field` API for `IntegerField(default=0)` to `FloatField(default=0)`. The model has an AutoField primary key, unique email and named partial balance index. The checked-in fixture avoids making Django a runtime or test dependency.
- `examples/rebuild_check/ledger.sql` and the migration examples next to it are original fixtures, with an audit trigger, partial index, unique constraint, a view, and an inbound cascading FK. sqlite-utils `Table.transform_sql` and Alembic batch SQL are generated fresh by the tests with the installed libraries (the Alembic test is skipped when Alembic and SQLAlchemy are not installed). Edge-case tests generate valid files with the real SQLite library, including STRICT, WITHOUT ROWID, composite FKs, deferred timing, sequences, FTS and generated columns.

No network is needed to run tests. No production/customer database is included.
